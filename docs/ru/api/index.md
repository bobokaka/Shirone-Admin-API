# Справочник API

Бэкенд Shirone-Admin — это локальная служба Fastify; интерфейс управления сам полностью работает через эту группу API. Вы можете вызывать их напрямую, используя Admin как **программируемый шлюз** к контент-репозиторию: пакетные скрипты, интеграция с внешними редакторами, автоматические конвейеры — всё возможно.

Раздел рассчитан на читателя, знакомого с HTTP и структурой контент-репозитория; материал сгруппирован по модулям бэкенда, для каждого эндпоинта приведены назначение, параметры, возвращаемое значение и минимальный работающий пример.

## Базовые соглашения

| Пункт | Значение |
|----|----|
| Базовый адрес | `http://127.0.0.1:5175` (меняется через `ADMIN_PORT`, привязка только к петлевому адресу машины) |
| Префикс путей | `/api` |
| Аутентификация | **Нет**. Локальный однопользовательский инструмент, в локальную сеть не открыт; не выставляйте его обратным прокси в интернет |
| Тело запроса | JSON (`bodyLimit` **2 МБ**); загрузка файлов через multipart (один файл ≤**30 МБ**, за раз один файл) |
| CORS | Полностью открыт (`origin: true`) — удобно отлаживать с любой локальной страницы |

## Формат ошибок

Все ошибки возвращают JSON с единственным полем `message` (на китайском) и подходящим HTTP-кодом:

```json
{ "message": "文件不存在" }
```

| Код | Источник |
|--------|------|
| `400` | Сбой бизнес-проверки (`ApiError`) или **провал zod-валидации запроса** — `message` вида `body.title: 标题不能为空`, склеивается по схеме «поле: причина» |
| `404` | Путь не существует или запрошенная статья/файл отсутствует (`ENOENT`) |
| `413` | Загружаемый файл превышает 30 МБ |
| `500` | Непредвиденная ошибка; `message` — исходный текст ошибки |

## Монтирование статических ресурсов

Три статических маршрута только для чтения напрямую отдают файлы репозиториев (если файл есть в контент-репозитории, отдаётся он, иначе откат к одноимённому пути репозитория темы); так реализован предпросмотр изображений в интерфейсе управления:

| Префикс | Обслуживаемая директория | Назначение |
|------|----------|------|
| `/content-assets/*` | `assets/` контент-репозитория (откат к `src/assets/` темы) | Предпросмотр ресурсов сборки: аватар, баннер и др. |
| `/content-public/*` | `public/` контент-репозитория (откат к `public/` темы) | Предпросмотр изображений моментов, музыки, обложек аниме |
| `/content-posts/*` | `content/posts/` контент-репозитория | Иллюстрации статей (превращение относительных ссылок `./images/…` в прямые) |

Все пути проходят проверку resolve и **не могут выйти за пределы корневого каталога** (защита от path traversal).

## Общее поведение

- **Цель записи**: кроме настроек ИИ (`server/data/ai-settings.json`), все записи происходят в контент-репозитории, на который указывает `CONTENT_DIR`
- **Параметры-пути**: параметры, обозначающие пути статей/моментов, — пути в стиле POSIX относительно контент-репозитория (например `hello/index.md`), с единым разделителем `/`
- **Форматы дат**: `published` статьи — `YYYY-MM-DD`; `publishedAt` — `YYYY-MM-DDTHH:mm:ss+08:00`; `published` момента — `YYYY-MM-DD HH:mm:ss`

## Быстрая проверка

Пока служба запущена, связность проверяется одной командой:

```bash
curl http://127.0.0.1:5175/api/status
```

Если в ответе вернулись пути контент-репозитория и репозитория темы, состояние подключения и сводка git — API готов.

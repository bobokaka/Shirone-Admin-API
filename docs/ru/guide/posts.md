# Управление статьями

Страница «Управление статьями» — главный вход в работу со статьями: просмотр всех статей, фильтрация по категориям и тегам, быстрый предпросмотр текста и массовое упорядочивание таксономии.

![Управление статьями](/assets/guide/posts.png)

Страница разделена на две панели: слева **список статей** (фильтры + выбор), справа **предпросмотр содержимого** (чтение или редактирование на месте). Кликните по любой статье слева — справа мгновенно отрисуется её Markdown-текст.

## Создание статьи

Нажмите на панели инструментов «**Создать статью**», введите заголовок в диалоге (после создания его можно менять в любой момент) и подтвердите:

1. Бэкенд создаст в контент-репозитории `content/posts/` статью в статусе **черновика**
2. Произойдёт автоматический переход на страницу [Редактирование статей](./post-editor.md) для письма

Из заголовка статьи транслитерацией пиньинья генерируется URL-дружелюбное имя каталога (slug), например 《快速上手指南》→ `kuai-su-shang-shou-zhi-nan/index.md`. При совпадении имён автоматически добавляется номер.

## Просмотр и фильтрация

Панель инструментов предлагает три фильтра, их можно комбинировать:

| Фильтр | Поведение |
|--------|------|
| Строка поиска | Одновременно ищет по **заголовку, категории и тегам** (без учёта регистра) |
| Выпадающий список категорий | Показывает только статьи категории; в скобках после варианта — число её статей |
| Выпадающий список тегов | Показывает только статьи с этим тегом |

Заголовок списка показывает «Статьи (после фильтра / всего)». Каждая строка статьи отображает заголовок, дату публикации, категорию и статусные метки: жёлтая «Черновик», «Закреплено», красная «С паролем».

## Предпросмотр и редактирование на месте

После выбора статьи справа показывается:

- **Заголовок и метаданные**: дата, категория, теги, метки черновик/закреплено/с паролем
- **Отрисовка текста**: Markdown рендерится в реальном времени; иллюстрации из каталога статьи (относительные ссылки `./images/…`) отображаются сразу
- Кнопка **«Редактировать»**: правая панель на месте переключается в полноценный редактор (тот же интерфейс, что на странице [Редактирование статей](./post-editor.md), только без двухпанельного предпросмотра). Значок «Раздельное редактирование» в правом верхнем углу редактора ведёт на полную страницу редактирования с предпросмотром слева и справа; при возврате состояние редактирования этой статьи восстанавливается автоматически
- Кнопка **«Удалить»**: для статьи-каталога выводится предупреждение «Будут удалены статья и все иллюстрации в её каталоге»; содержимое, уже попавшее в git-историю, можно восстановить

> [!TIP]
> При переключении статьи слева в режиме редактирования на месте несохранённые изменения **сначала автоматически сохраняются без звука** и только затем происходит переключение — текст не потеряется (подробнее: [Редактирование статей · Автосохранение](./post-editor.md#автосохранение)).

## Управление категориями и тегами

Кнопка «**Управление категориями**» справа на панели инструментов открывает диалог массового упорядочивания — единственное место, где нужно поддерживать таксономию всего сайта:

- Сверху две вкладки — категории и теги; списки отсортированы по **числу использующих статей по убыванию**
- **Переименовать / объединить**: категория (или тег) получает новое имя; если такое имя уже существует, происходит **слияние**. Бэкенд перепишет frontmatter каждой статьи, сохранив формат дат
- **Удалить**: убрать эту категорию/тег из всех статей (сами статьи не затрагиваются)

Например, хотите объединить разбросанные «JS» и «JavaScript» в «JavaScript»: выполните переименование «JS», введите `JavaScript` — после подтверждения все затронутые статьи перепишутся автоматически.

## Как статьи хранятся на диске

Понимание формы хранения облегчит резервное копирование и диагностику:

```
content/posts/
├── hello/                  # каталогом (по умолчанию для новых статей): иллюстрации рядом с текстом
│   ├── index.md
│   └── images/
│       └── cover.webp
└── old-post.md             # плоско (исторические статьи или импорт извне): один файл
```

- Новые статьи всегда создаются **каталогом**; загруженные в редакторе иллюстрации автоматически попадают в подкаталог `images/` этого каталога
- Список отсортирован по принципу **закреплённые сверху, далее по дате публикации по убыванию**

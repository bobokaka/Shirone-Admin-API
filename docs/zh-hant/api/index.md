# API 參考

Shirone-Admin 的後端是一個本地 Fastify 服務，管理介面本身完全透過這組 API 工作。你也可以直接呼叫它們，把 Admin 當作內容倉的**可程式化閘道**使用——批次腳本、外部編輯器對接、自動化管線都可行。

本板塊面向熟悉 HTTP 與內容倉結構的讀者，按後端模組分組，每個端點給出用途、參數、回傳值與最小可執行示例。

## 基礎約定

| 項 | 值 |
|----|----|
| 基礎位址 | `http://127.0.0.1:5175`（`ADMIN_PORT` 可改，僅綁定本機回送） |
| 路徑前綴 | `/api` |
| 鑑權 | **無**。本地單機工具，不暴露到區域網路，請勿反向代理到對外網路 |
| 請求主體 | JSON（`bodyLimit` **2MB**）；檔案上傳走 multipart（單檔案 ≤**30MB**，一次一個檔案） |
| CORS | 全開（`origin: true`），方便本地任意頁面除錯 |

## 錯誤格式

所有錯誤返回 JSON 單欄位 `message`（中文），配合恰當的 HTTP 狀態碼：

```json
{ "message": "文件不存在" }
```

| 狀態碼 | 來源 |
|--------|------|
| `400` | 業務驗證失敗（`ApiError`）或 **zod 請求驗證失敗**——`message` 形如 `body.title: 标题不能为空`，按「欄位: 原因」串接 |
| `404` | 路徑不存在，或請求的文章/檔案等目標缺失（`ENOENT`） |
| `413` | 上傳檔案超過 30MB |
| `500` | 未預期錯誤，`message` 為原始錯誤訊息 |

## 靜態資源掛載

三個唯讀靜態路由直接服務內容倉檔案（內容倉命中則用內容倉，否則回退主題倉同名路徑），管理介面的圖片預覽即由此實現：

| 前綴 | 服務目錄 | 用途 |
|------|----------|------|
| `/content-assets/*` | 內容倉 `assets/`（回退主題倉 `src/assets/`） | 頭像、橫幅等建置期資源預覽 |
| `/content-public/*` | 內容倉 `public/`（回退主題倉 `public/`） | 說說圖、音樂、番劇封面預覽 |
| `/content-posts/*` | 內容倉 `content/posts/` | 文章配圖（`./images/…` 相對引用的直鏈化） |

所有路徑都經過 resolve 驗證，**無法越出根目錄**（防目錄穿越）。

## 通用行為說明

- **寫入目標**：除 AI 設定（`server/data/ai-settings.json`）外，一切寫入都發生在 `CONTENT_DIR` 指向的內容倉
- **路徑參數**：涉及文章/說說路徑的參數均為相對內容倉的 POSIX 風格路徑（如 `hello/index.md`），統一以 `/` 分隔
- **日期格式**：文章 `published` 為 `YYYY-MM-DD`；`publishedAt` 為 `YYYY-MM-DDTHH:mm:ss+08:00`；說說 `published` 為 `YYYY-MM-DD HH:mm:ss`

## 快速驗證

服務在跑的時候，一條命令確認連通性：

```bash
curl http://127.0.0.1:5175/api/status
```

返回內容倉與主題倉路徑、連接狀態與 git 概要，即說明 API 就緒。

# API リファレンス

Shirone-Admin のバックエンドはローカルの Fastify サービスで、管理インターフェース自体が完全にこの API 群で動いています。あなたが直接呼び出すこともでき、Admin をコンテンツリポジトリの**プログラマブルゲートウェイ**として使えます——バッチスクリプト、外部エディターとの連携、自動化パイプライン、すべて可能です。

このセクションは HTTP とコンテンツリポジトリの構造に慣れた読者向けです。バックエンドのモジュールごとにグループ化し、各エンドポイントの用途、パラメーター、戻り値、最小限の動作例を示します。

## 基本取り決め

| 項目 | 値 |
|----|----|
| ベース URL | `http://127.0.0.1:5175`（`ADMIN_PORT` で変更可。ホストのループバックのみにバインド） |
| パスプレフィックス | `/api` |
| 認証 | **なし**。ローカル単体ツールで、LAN には公開されません。インターネットへリバースプロキシしないでください |
| リクエストボディ | JSON（`bodyLimit` は **2MB**）。ファイルアップロードは multipart（1ファイル ≤**30MB**、1回 1ファイル） |
| CORS | 全面許可（`origin: true`）。ローカルの任意のページでのデバッグに便利 |

## エラーフォーマット

すべてのエラーは単一フィールド `message`（中国語）の JSON を、適切な HTTP ステータスコードとともに返します：

```json
{ "message": "文件不存在" }
```

| ステータスコード | 由来 |
|--------|------|
| `400` | 業務バリデーション失敗（`ApiError`）または **zod のリクエスト検証失敗**——`message` は `body.title: 标题不能为空` のような「フィールド: 理由」形式 |
| `404` | パスが存在しない、またはリクエスト対象の記事/ファイル等がない（`ENOENT`） |
| `413` | アップロードファイルが 30MB 超過 |
| `500` | 予期しないエラー。`message` は生のエラーメッセージ |

## 静的リソースのマウント

3つの読み取り専用静的ルートが、コンテンツリポジトリのファイルを直接提供します（コンテンツリポジトリに存在すればそちらを、なければテーマリポジトリの同名パスにフォールバック）。管理インターフェースの画像プレビューはこれで実現されています：

| プレフィックス | 提供ディレクトリ | 用途 |
|------|----------|------|
| `/content-assets/*` | コンテンツリポジトリ `assets/`（フォールバック：テーマリポジトリ `src/assets/`） | アバター、バナーなど構築期リソースのプレビュー |
| `/content-public/*` | コンテンツリポジトリ `public/`（フォールバック：テーマリポジトリ `public/`） | モーメンツ画像、音楽、アニメカバーのプレビュー |
| `/content-posts/*` | コンテンツリポジトリ `content/posts/` | 記事の画像（`./images/…` 相対参照の直リンク化） |

すべてのパスは resolve 検証を通り、**ルートディレクトリの外へ出ることはできません**（ディレクトリトラバーサル対策）。

## 共通の動作

- **書き込み先**：AI 設定（`server/data/ai-settings.json`）を除き、すべての書き込みは `CONTENT_DIR` が指すコンテンツリポジトリで行われます
- **パスパラメーター**：記事/モーメンツのパスを含むパラメーターは、すべてコンテンツリポジトリからの相対 POSIX 形式パスです（例：`hello/index.md`）。区切りは `/` に統一
- **日付フォーマット**：記事の `published` は `YYYY-MM-DD`。`publishedAt` は `YYYY-MM-DDTHH:mm:ss+08:00`。モーメンツの `published` は `YYYY-MM-DD HH:mm:ss`

## 動作確認

サービスが動いているとき、コマンド 1つで接続を確認できます：

```bash
curl http://127.0.0.1:5175/api/status
```

コンテンツリポジトリとテーマリポジトリのパス、接続状態、git 概要が返ってくれば、API の準備はできています。

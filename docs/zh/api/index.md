# API 参考

Shirone-Admin 的后端是一个本地 Fastify 服务，管理界面本身完全通过这组 API 工作。你也可以直接调用它们，把 Admin 当作内容仓的**可编程网关**使用——批量脚本、外部编辑器对接、自动化流水线都可行。

本板块面向熟悉 HTTP 与内容仓结构的读者，按后端模块分组，每个端点给出用途、参数、返回值与最小可运行示例。

## 基础约定

| 项 | 值 |
|----|----|
| 基础地址 | `http://127.0.0.1:5175`（`ADMIN_PORT` 可改，仅绑定本机回环） |
| 路径前缀 | `/api` |
| 鉴权 | **无**。本地单机工具，不暴露到局域网，请勿反代到公网 |
| 请求体 | JSON（`bodyLimit` **2MB**）；文件上传走 multipart（单文件 ≤**30MB**，一次一个文件） |
| CORS | 全开（`origin: true`），方便本地任意页面调试 |

## 错误格式

所有错误返回 JSON 单字段 `message`（中文），配合恰当的 HTTP 状态码：

```json
{ "message": "文件不存在" }
```

| 状态码 | 来源 |
|--------|------|
| `400` | 业务校验失败（`ApiError`）或 **zod 请求校验失败**——`message` 形如 `body.title: 标题不能为空`，按「字段: 原因」拼接 |
| `404` | 路径不存在，或请求的文章/文件等目标缺失（`ENOENT`） |
| `413` | 上传文件超过 30MB |
| `500` | 未预期错误，`message` 为原始错误信息 |

## 静态资源挂载

三个只读静态路由直接服务内容仓文件（内容仓命中则用内容仓，否则回退主题仓同名路径），管理界面的图片预览即由此实现：

| 前缀 | 服务目录 | 用途 |
|------|----------|------|
| `/content-assets/*` | 内容仓 `assets/`（回退主题仓 `src/assets/`） | 头像、横幅等构建期资源预览 |
| `/content-public/*` | 内容仓 `public/`（回退主题仓 `public/`） | 说说图、音乐、番剧封面预览 |
| `/content-posts/*` | 内容仓 `content/posts/` | 文章配图（`./images/…` 相对引用的直链化） |

所有路径都经过 resolve 校验，**无法越出根目录**（防目录穿越）。

## 通用行为说明

- **写入目标**：除 AI 设置（`server/data/ai-settings.json`）外，一切写入都发生在 `CONTENT_DIR` 指向的内容仓
- **路径参数**：涉及文章/说说路径的参数均为相对内容仓的 POSIX 风格路径（如 `hello/index.md`），统一 `/` 分隔
- **日期格式**：文章 `published` 为 `YYYY-MM-DD`；`publishedAt` 为 `YYYY-MM-DDTHH:mm:ss+08:00`；说说 `published` 为 `YYYY-MM-DD HH:mm:ss`

## 快速验证

服务在跑的时候，一条命令确认连通性：

```bash
curl http://127.0.0.1:5175/api/status
```

返回内容仓与主题仓路径、连接状态与 git 概要，即说明 API 就绪。

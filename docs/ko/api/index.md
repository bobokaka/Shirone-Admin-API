# API 참조

Shirone-Admin의 백엔드는 로컬 Fastify 서비스이며, 관리 인터페이스 자체도 완전히 이 API 묶음으로 동작합니다. 여러분이 이들을 직접 호출해 Admin을 콘텐츠 저장소의 **프로그래밍 가능한 게이트웨이**로 쓸 수도 있습니다 — 배치 스크립트, 외부 에디터 연동, 자동화 파이프라인 모두 가능합니다.

이 섹션은 HTTP와 콘텐츠 저장소 구조에 익숙한 독자를 대상으로 하며, 백엔드 모듈별로 묶어 각 엔드포인트의 용도, 매개변수, 반환값, 최소 실행 예제를 제공합니다.

## 기본 규약

| 항목 | 값 |
|----|----|
| 기본 주소 | `http://127.0.0.1:5175`(`ADMIN_PORT`로 변경 가능, 로컬 루프백에만 바인딩) |
| 경로 접두사 | `/api` |
| 인증 | **없음**. 로컬 단독 도구로 LAN에 노출되지 않으니, 공인망으로 리버스 프록시하지 마세요 |
| 요청 본문 | JSON(`bodyLimit` **2MB**); 파일 업로드는 multipart(파일 하나당 ≤**30MB**, 한 번에 한 파일) |
| CORS | 전부 허용(`origin: true`). 로컬의 어떤 페이지로도 디버깅하기 쉽도록 |

## 오류 형식

모든 오류는 단일 필드 `message`(중국어)를 담은 JSON을 적절한 HTTP 상태 코드와 함께 반환합니다:

```json
{ "message": "文件不存在" }
```

| 상태 코드 | 발생 원인 |
|--------|------|
| `400` | 비즈니스 검증 실패(`ApiError`) 또는 **zod 요청 검증 실패** — `message`는 `body.title: 标题不能为空` 같은 형태로 「필드: 이유」를 이어 붙임 |
| `404` | 경로가 없거나 요청한 글/파일 등의 대상이 없음(`ENOENT`) |
| `413` | 업로드 파일이 30MB 초과 |
| `500` | 예기치 못한 오류. `message`는 원본 오류 메시지 |

## 정적 리소스 마운트

세 개의 읽기 전용 정적 라우트가 콘텐츠 저장소 파일을 직접 서빙합니다(콘텐츠 저장소에 있으면 그것을 쓰고, 없으면 테마 저장소의 같은 이름 경로로 대체). 관리 인터페이스의 이미지 미리보기가 바로 이것으로 구현됩니다:

| 접두사 | 서빙 디렉터리 | 용도 |
|------|----------|------|
| `/content-assets/*` | 콘텐츠 저장소 `assets/`(대체: 테마 저장소 `src/assets/`) | 아바타, 배너 등 빌드 시점 리소스 미리보기 |
| `/content-public/*` | 콘텐츠 저장소 `public/`(대체: 테마 저장소 `public/`) | 모먼트 이미지, 음악, 애니메이션 표지 미리보기 |
| `/content-posts/*` | 콘텐츠 저장소 `content/posts/` | 글 첨부 이미지(`./images/…` 상대 참조의 직접 링크화) |

모든 경로는 resolve 검증을 거쳐 **루트 디렉터리를 벗어날 수 없습니다**(경로 탈출 방지).

## 공통 동작 설명

- **쓰기 대상**: AI 설정(`server/data/ai-settings.json`)을 제외한 모든 쓰기는 `CONTENT_DIR`이 가리키는 콘텐츠 저장소에서 일어납니다
- **경로 매개변수**: 글/모먼트 경로와 관련된 매개변수는 모두 콘텐츠 저장소 기준 POSIX 스타일 상대 경로입니다(예: `hello/index.md`). 구분자는 통일된 `/`
- **날짜 형식**: 글의 `published`는 `YYYY-MM-DD`; `publishedAt`은 `YYYY-MM-DDTHH:mm:ss+08:00`; 모먼트의 `published`는 `YYYY-MM-DD HH:mm:ss`

## 빠른 확인

서비스가 돌고 있을 때 한 줄로 연결을 확인합니다:

```bash
curl http://127.0.0.1:5175/api/status
```

콘텐츠 저장소와 테마 저장소 경로, 연결 상태, git 요약이 반환되면 API가 준비된 것입니다.

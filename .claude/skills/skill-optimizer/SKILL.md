# Skill Optimizer

> **Context:** 当用户要求审查、检查或优化 Skill 文档质量时使用
> **Objective:** 系统性审查 Skill 文档，输出结构化评分报告和修复建议
> **Style:** 结构化技术报告风格
> **Tone:** 专业、客观、可执行
> **Audience:** Claude Code 用户和 Skill 开发者
> **Response:** 按固定模板输出审查报告，包含评分、问题清单和修复建议

当用户要求审查 Skill 文档时，按以下步骤执行系统性审查。

## 背景

Skill 文档是 AI 执行指令的载体，文档质量直接影响 AI 的执行效果。一份高质量的 Skill 文档应具备：
- **结构清晰**: Front Matter 完整，章节层次分明
- **指令明确**: 触发条件清晰，执行步骤可操作
- **内容精炼**: 无冗余信息，避免浪费 token

## 核心功能

1. **自动化检测**: 检查 Front Matter、文件命名、代码块标识等可量化指标
2. **语义审查**: 评估 CO-STAR 声明、Description 规范、示例场景等质量指标
3. **无意义内容审计**: 识别并建议删除更新日志、致谢等对执行无帮助的内容
4. **评分报告**: 输出结构化的评分和修复建议

## 执行步骤

### 步骤 1: 读取目标文件

使用 Read 工具读取用户指定的 Skill 文件。

如果用户未指定文件:

```bash
find skills/ -name "SKILL.md" -type f
```

列出所有文件供用户选择。

### 步骤 2: 自动化检测 (第一层)

运行以下检测并记录结果:

````bash
# 2.1 Front Matter 字段计数
FILE="目标文件路径"
echo "Front Matter 字段:"
grep -E "^name:|^description:|^version:|^updateTime:|^tags:|^difficulty:" "$FILE" | wc -l

# 2.2 文件结构检查
basename "$(dirname "$FILE")" | grep -qE "^[a-z][a-z0-9-]*$" && echo "结构: ✅" || echo "结构: ❌"

# 2.3 行数检查
wc -l < "$FILE"

# 2.4 无标识代码块检查
grep '```$' "$FILE" | grep -v '```[a-zA-Z]*' | wc -l

# 2.5 必需章节检查
grep "^## " "$FILE" | grep -cE "背景|概述|核心功能|环境要求|使用步骤|示例|场景|规则|最佳实践|常见问题|FAQ|参考资源"

# 2.6 无意义内容检测 (新增)
echo "=== 无意义内容检测 ==="
# 检测更新日志章节
if grep -q "^##.*更新日志\|^##.*Changelog\|^##.*更新记录" "$FILE"; then
    echo "⚠️ 发现更新日志章节 (浪费行数，对skill功能无意义)"
    grep -n "^##.*更新日志\|^##.*Changelog" "$FILE" | head -1
fi
# 检测空章节（只有标题无内容）
for line in $(grep -n "^##" "$FILE" | cut -d: -f1); do
    next_line=$((line + 1))
    if sed -n "${next_line}p" "$FILE" | grep -q "^##"; then
        echo "⚠️ 第 $line 行: 空章节 (连续标题)"
    fi
done
````

**记录每项检测结果，格式: `项目: 结果/标准`**

### 步骤 3: 语义审查 (第二层)

检查以下内容:

**3.1 CO-STAR 框架检查**

- 文件开头是否有 CO-STAR 声明块?
- 包含 Context、Objective、Style、Tone、Audience、Response 中的几个?

**3.2 Description 字段检查**

- 是否第三人称? (不含"我"、"可以"、"帮助")
- 是否包含触发条件? (说明何时使用)

**3.3 示例场景检查**

- 统计 `### 场景` 或 `### 示例` 的数量
- 是否覆盖基础、进阶、复杂三级?

**3.4 术语一致性检查**

```bash
# 检查大小写不一致 (应统一使用 Skill)
grep -o "\bSkill\b" "$FILE" | wc -l
grep -o "\bskill\b" "$FILE" | wc -l
```

**3.5 无意义内容审计** (核心检测)

Skill 文档应专注于**可执行指令**，以下内容被视为"无意义"且应删除：

| 内容类型               | 检测方法                                           | 扣分  | 处理建议                             |
| ---------------------- | -------------------------------------------------- | ----- | ------------------------------------ |
| **更新日志/Changelog** | `grep "^##.*更新日志\|^##.*Changelog"`             | -15   | 直接删除，version 字段已含版本信息   |
| **致谢/贡献者列表**    | `grep "^##.*致谢\|^##.*贡献者\|^##.*Contributors"` | -10   | 移至项目 README，非 Skill 核心功能   |
| **TODO/Future 计划**   | `grep "^##.*TODO\|^##.*未来计划\|^##.*Roadmap"`    | -8    | 未实现内容不应在 Skill 文档中        |
| **许可证声明**         | `grep "^##.*License\|^##.*许可"`                   | -5    | 移至项目根目录                      |
| **重复的规则说明**     | 相同内容出现 ≥3 次                                 | -5    | 合并或删除重复                      |
| **空章节**             | 连续 `##` 标题                                     | -3/个 | 删除或补充内容                      |
| **过度装饰**           | 大量 emoji/分隔线 (每10行>1个)                     | -3    | 精简装饰                            |

**检测命令:**

```bash
# 统计无意义内容行数
CHANGELOG_LINES=$(sed -n '/^##.*更新日志\|^##.*Changelog/,/^##/p' "$FILE" | wc -l)
echo "更新日志占用行数: $CHANGELOG_LINES"
```

### 步骤 4: 计算评分

**自动检测评分 (35分):**

- Front Matter: 满分 7 分 (字段数 / 6 × 7)
- 文件命名: 满分 5 分 (符合 5 / 不符合 0)
- 文档行数: 满分 8 分 (≤500 为 8 分，每超 50 行扣 1 分)
- 代码块标识: 满分 8 分 (0 缺失为 8 分，每 1 个缺失扣 2 分)
- 必需章节: 满分 7 分 (章节数 / 8 × 7)

**语义审查评分 (45分):**

- CO-STAR 声明: 满分 15 分
  - 有声明块: 3 分
  - 每个要素: 2 分 (Context/Objective/Style/Tone/Audience/Response)
- Description 规范: 满分 15 分
  - 第三人称: 8 分 (含"我/可以/帮助"扣 8 分)
  - 有触发条件: 7 分 (含"在...时使用"等关键词)
- 示例场景: 满分 10 分
  - 0-1 个: 0 分
  - 2 个: 3 分
  - 3 个且覆盖三级: 10 分
- 术语一致性: 满分 5 分
  - 一致: 5 分
  - 不一致: 0 分

**无意义内容评分 (20分):**

| 检测项       | 满分 | 扣分规则    |
| ------------ | ---- | ----------- |
| 更新日志     | 5    | 存在扣 5 分 |
| 致谢/贡献者  | 3    | 存在扣 3 分 |
| TODO/Roadmap | 3    | 存在扣 3 分 |
| 许可证章节   | 2    | 存在扣 2 分 |
| 空章节       | 3    | 每个扣 1 分 |
| 重复内容     | 2    | 存在扣 2 分 |
| 过度装饰     | 2    | 存在扣 2 分 |

**总分 = 自动检测分 + 语义审查分 + 无意义内容分**

**评级:**

- ≥90: ✅ 优秀
- 70-89: ✅ 合格
- <70: ❌ 不合格

**注意:** 无意义内容扣分可能导致总分超过 100 分基准（反向扣分制），最终得分按 `max(0, 总分)` 计算。

### 步骤 6: 等待用户确认

询问用户是否需要:

1. **自动修复** (推荐，对于无意义内容可安全删除)
2. **手动修复指导**
3. **重新审查**

**自动清理无意义内容**:

如果用户选择自动修复，按以下优先级执行清理:

```bash
# 优先级1: 删除更新日志 (浪费行数，对功能无意义)
# 查找章节起始和结束行
START=$(grep -n "^##.*更新日志\|^##.*Changelog" "$FILE" | cut -d: -f1 | head -1)
if [ -n "$START" ]; then
    # 找到下一个章节标题
    END=$(tail -n +$((START+1)) "$FILE" | grep -n "^##" | head -1 | cut -d: -f1)
    if [ -n "$END" ]; then
        END=$((START + END - 1))
    else
        END=$(wc -l < "$FILE")
    fi
    # 删除章节
    sed -i "${START},${END}d" "$FILE"
fi

# 优先级2: 删除空章节
# (连续 ## 标题，删除第一个)
```

**注意**: 删除前必须征得用户明确同意。

## 规范参考

### Front Matter 必需格式

```yaml
---
name: skill-name # kebab-case
description: '功能描述。在触发条件时使用。' # 第三人称 + 触发条件
version: 1.0.0 # 语义化版本
updateTime: 2026-01-15 # YYYY-MM-DD
tags: [tag1, tag2]
difficulty: beginner # beginner|intermediate|advanced
---
```

### 描述字段正确示例

✅ `'生成Vue3组件。在创建.vue文件或Vue组件时使用。'`
❌ `'帮你生成Vue组件'`

### CO-STAR 声明格式

```markdown
> **Context:** 何时使用此 Skill
> **Objective:** 要达成什么目标
> **Style:** 输出风格要求
> **Tone:** 交互语气
> **Audience:** 目标用户
> **Response:** 输出格式
```

## 常见问题处理

**Q: 用户要求批量审查?**

```bash
for file in $(find skills/ -name "SKILL.md" -type f); do
    echo "=== 审查 $file ==="
    # 执行步骤 1-5
done
```

**Q: 发现更新日志等无意义内容?**

1. 报告中明确标注 🗑️ 无意义内容分类
2. 说明删除原因 (对 Skill 执行功能无意义，浪费 token)
3. 询问用户是否自动删除

**Q: 无意义内容检测优先级?**

1. **高优先级:** 更新日志、致谢、许可证
2. **中优先级:** TODO/Roadmap、空章节
3. **低优先级:** 重复内容、过度装饰
